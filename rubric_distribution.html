Rubric libraries: can a judge with rubrics stand in for running code?

Built 2026-09-29 15:49 · every library ever tried: detailed record · index

Experiment setup

  • Agent: Claude Haiku 4.5 working in a sandbox on each task. Judge: Claude Opus 5.
  • Benchmarks: MLE-bench Lite (22 Kaggle competitions; measured: valid submission, medal, above median) and PaperBench (20 ICML 2024 papers to reproduce; score 0 to 1, graded by Claude Sonnet 5.5).
  • References: Ceiling: every command the agent runs is executed for real and it sees the output, no judge. Floor: no feedback, code-running commands return a fixed notice, no judge.
  • Judge rows: instead of running the agent's code, the judge reads each code change against 12 rubrics and predicts whether it works; the agent sees the predicted reward and each applicable rubric's 0/1. The same final harness everywhere: the judge also sees a read-only view of the sandbox and data and the last real run, a clean verdict runs the command for real, and on submit the deliverable runs (capped) before it is accepted.
  • Where rubrics come from: the collection pool, the same Haiku agent's rollouts on other benchmarks (InfiAgent-DABench, DA-Code, DSBench, MLGym, MLAgentBench, RE-Bench for MLE-bench; SUPER research repositories for PaperBench), filtered so no task resembles a benchmark task. Every failure in it is labelled by Sonnet 5.5 into one of 22 categories.
  • Row names: curation method · retrieval method. Up to three runs per row.

Rubric curation methods

Wrong-answerThe original pipeline. Opus reads only rollouts whose final answer was graded wrong (first collection, one-CSV data-analysis tasks) and writes one rubric per rollout from the final scripts and answer. 1,000 rubrics, no matching.
Crash-rubricOne rubric per crashed command of the MLE-bench collection pool (what made the run die, written as a precondition a reviewer can see in the code). No matching. Used on PaperBench as the earlier method.
UnmatchedOpus reads each whole rollout of the collection pool (every command and output, the scripts, the answer, the verdict) and writes up to 6 rubrics; everything is kept (near-duplicates removed). No matching.
FilteredDistribution matching by filtering: the whole-rollout library, each rubric put in a failure category, keeps per category only as many rubrics as that category's share of the collection pool's failures allows. The scarcest category sets the size (220 of 3,550 rubrics survive).
QuotaDistribution matching at curation time: choose the size (1,000) and the collection pool's failure mix first; Opus writes rubrics from each category's own failures until that category's quota is full, and a full category gets no more calls. A rubric counts toward the category of the failure it came from (952 rubrics).

Retrieval methods

SimilarityEach time the agent runs code, the judge gets the 12 rubrics most similar to the task and the code change (text embeddings), from the whole library.
Category splitThe 12 slots are first divided across failure categories in the target proportions (each category's share of the failures its rubrics cover), then each category's slots go to its rubrics most similar to the task and code change.

What the latest results say

  • Crash-rubric · Similarity (a library from the MLE-bench pool) is the only row clearly above the floor.
  • Quota · Category split from PaperBench's own pool is inside noise; that library came out short and off its target (628 of 999 rubrics: that pool's API and environment failures repeat the same few lessons).
  • Ceiling = floor. PaperBench's score is half code development (graded by reading the code) and half execution and results; the second half is near zero for every row, because nothing reproduces a paper's results in 90 minutes. So execution feedback barely moves the score, while a judge that reads the code against rubrics targets the half that is earned.

No mismatch chart here: PaperBench's collection pool and its benchmark were labelled in different category sets.

Both benchmarks have been used to find what goes wrong, so these are development-set numbers.
