MLE-bench Lite — canonical hybrid CWM

MLE-bench Lite, all 21 competitions held out · Haiku 4.5 agent · official mlebench grader · 2-hour budget per competition · rubrics collected from external data-science task pools only (270 pool rollouts, 69 failures, 69 lessons: the library is 10 / all = 69, and the "100" arms are replicates of "all") · canonical architecture: routed commands are never run (hybrid: code execution; all-CWM: everything); the agent receives only the parsed rubric → reward verdicts as markdown

1Experiment setting

Each task is a Kaggle competition: the agent gets the competition description and data and must leave a valid submission file; the official grader scores it against the real leaderboard. Medal = the submission clears the bronze threshold; the table also reports the above-median rate and valid submissions.

A Haiku 4.5 agent works in the repository by issuing bash commands. The settings differ only in what answers those commands:

Canonical hybrid CWM architecture (these are real runs, not mocks). Every command the agent issues goes through a router. A command that does not run code (reads, searches, edits, git diff) is executed in the pod and the agent sees its real output. A command that runs code (python x.py, pytest, python -c, make, shell scripts, profilers and launcher wrappers such as strace or timeout) is never run: the world model grades the agent's current change set instead, and the only thing the agent receives is the parsed rubric verdicts rendered as markdown. Nothing else comes back: no simulated output, no rationale, no exit code of a run that never happened.

agent (Haiku 4.5) ── bash command ──▶ ROUTER: does this command run code?
                                        │
        no: ls / cat / grep / sed -i / cat > file / git diff …
                                        ├──▶ pod runs it ──▶ real stdout + exit code ──▶ agent
        yes: python x.py / pytest / python -c / make / bash run.sh / strace … / timing tools …
                                        └──▶ NEVER RUN.  Instead:
                                               1. git diff HEAD of the pod's working tree   (the agent's edits so far)
                                               2. retrieve the top-12 rubrics nearest to the task (embedding search
                                                  over the mined library; none in the "no library" arm)
                                               3. judge (Opus 5, fast mode; Haiku 4.5 in the haiku-* arms) reads
                                                  task + diff + rubrics  ──▶  JSON {rubric: {applies, violated}}
                                               4. reward = 1 − violated / applicable
                                               5. rendered as markdown = the agent's whole observation:

                                                  Predicted reward: 0.67 (1 of 3 applicable criteria violated; 9 not applicable)
                                                  Violated (failure pattern present in your change):
                                                  - <rubric title>
                                                  Checked, not violated:
                                                  - <rubric title> …

                                               no edits yet  ──▶  "Predicted reward: 0.00 (no code change yet)"
submit ──▶ harness takes the real git diff HEAD of the pod ──▶ hidden tests (SWE-bench) / competition grader (MLE-bench)

Arms differ only in the judge model (Opus / Haiku), the rubric library (none, 10, 100, 1000 mined rubrics, or 12 random ones) and the routing: the interpreter has no router (everything runs for real); no code exec. routes the same commands but has no judge at all (the agent gets <execution output withheld>, the floor); hybrid, no library keeps the Opus judge with only the task criterion; all-CWM routes every command, so the agent's edits never reach the working tree and its patch is empty; the simulator routes every command to an Opus model that predicts the output and exit code. Nothing in any world-model arm executes the code the agent wrote.

Exploration arms (not part of the 9/07 method set)

Cost-gated hybrid: cheap execution commands run for real with real output; expensive ones (workload timings, rebuilds, test suites, anything that took over 30 s before) are graded first and run for real only when the judge finds no violations, at most 3 times per task; the learned variant gates only commands that took over 30 s earlier in the task, baselines stay free. Race: every execution command starts for real in the background while the judge grades the diff; the faster answer is the observation and a slow run's real output is attached to a later observation. Strict JSON channel: the agent receives only the parsed rubric → reward JSON from the judge (no preamble, rationale or prediction text).

4Curation cost per rubric

On-policy mining from the DABench + DA-Code data-science pool (run_da_pool.py): the same Haiku agent runs on pool tasks with real execution, every failed rollout is distilled into one lesson by Opus, lessons are deduplicated and cut into the 10 / 100 / all libraries. No CWM grading during mining and no precision filter, so the per-rubric cost is the "cheap" recipe of the SWE-bench page. Prices: Opus 5 $5 / $25 per M tokens, Haiku 4.5 $1 / $5, GKE Spot ≈ $0.045 per node-hour.
