1The method

The agent is a Haiku 4.5 loop issuing bash commands. Each command is routed by a classifier:

  • Reads, edits, navigation (cat, grep, sed, git diff, heredoc writes) go to the real interpreter.
  • Code execution (pytest, python x.py, python -c, bash -c, ./script, $(python …)) still runs for its side effects, but its output is replaced by the coding world model (CWM): the model reads the task, the current diff (probe files included) and the command, grades the diff against a set of criteria — retrieved from a rubric library or the standing task criterion — and the agent sees that verdict plus the real return code.
  • Files written by a run are quarantined so the agent cannot read the output back; every trace is audited for leakage.

The hidden grading tests are never available to the agent in any arm; the interpreter baseline only runs what the agent chooses to run.

3What it says

  • Reading the code is worth ~50 points; running it is worth ~9 more. All-CWM (no readable output) ≈ 12%; bash-only 63.6%; interpreter 72.4%.
  • At the agent's own strength, the rubric CWM is worth nothing: Haiku judge + 1000-rubric retrieval = 63.0%, indistinguishable from no execution feedback (p = 0.81).
  • With an Opus judge it is worth +12 points over the floor and +3 over the interpreter — but the same judge shown to the agent as a bare reward drops back to the floor (62.8%), so the gain is the judge's explanations, i.e. coaching by a stronger model, not evaluation.
  • Library size, source, retrieval vs random: no measurable effect under either judge (details: RUBRIC_DIAGNOSIS.md §10–§16).
