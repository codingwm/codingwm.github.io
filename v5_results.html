SimCode v5: can a decision model replace most code execution?

Built 2026-10-11 12:43 · profile v5 · 10,000 bootstrap draws · index

Experiment setupHaiku 5.5 agent; decision models replace most real program runs; MLE-bench (53 + Lite), NatureBench (primary held-out), PaperBench.
  • Agent: Claude Haiku 5.5 in a minimal shell-tool scaffold (one or more bash calls per step); every arm shares the agent, sandbox, hardware envelope and time limit.
  • Decision model (DM): judges a code-execution step against rubrics mined from earlier runs and returns only numbers (applies, reward) per rubric. The agent sees the step reward and the text of each applicable rubric.
  • MLE-bench: results are reported on the 53 competitions outside Lite. An earlier harness (v4, Haiku 4.5) was run once on all 75 and only its aggregate scores were read; no v5 choice was tuned on them. Lite (22) is a development set, reported separately. Valid submission, medal and above-median rates.
  • NatureBench: the primary held-out set, NatureBench-25 plus OpenRSI's Lite-v2 (32 tasks); official leaderboard metrics on the end-of-episode run: scored (a valid final output; the validity judge is not run, so this stands in for completion), Match-SOTA (g ≥ 0), mean g.
  • PaperBench: 20 papers, replication score.
  • Seeds: 3 for SimCode, the interpreter, checks-only and the floor on MLE-bench and NatureBench; 1 otherwise. A task's value is its mean over seeds; an arm's number is the mean over tasks.
  • Confidence intervals: 95%, task-clustered bootstrap (tasks resampled with all their seeds). Paired differences are per task, seed-paired when both arms ran the same seeds.
  • Infrastructure failures (retrieval configuration error, lost pod, missing final exit record, PaperBench grader not run) are excluded from every rate and counted in the accounting table, never scored as failures.
